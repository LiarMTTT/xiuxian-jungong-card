## 一、核心玩法

- 玩家可以在地图与实际旅行中使用堪舆能力，主动搜索当前位置附近尚未发现的隐藏内容。
- 堪舆能力不是单一按钮属性，而是由 {{user}} 当时真实拥有的神识、风水／堪舆术法、相关知识、法宝、现场观察与其他有效条件共同决定。
- 可发现内容至少包括：未公开遗迹、灵脉、修士洞府以及具有世界内实体入口的副本或秘境。
- “尚未发现”以玩家当前掌握的情报为准，不表示该地点在世界上无人知晓、无人使用或无人占有。
- 修士洞府可能仍有主人、已经遗弃，或因原主人坐化而封存；“发现”不自动等于无主、安全、合法占有或能够立刻开启。
- 发现线索、定位入口、解析禁制、实际进入、确认归属、取得资源和改变地点是不同环节，不能被一次堪舆自动合并结算。
- 搜索范围首先是玩家附近与实际可感知区域，不是打开地图后无条件扫描整个九域。
- 玩家没有相应能力时仍可通过传闻、地图、追踪、购买情报、偶遇和其他开放世界方式发现内容；堪舆是重要探索路径，但不是唯一入口。
- 这项入世后的探索能力不改写“降临地点免费”：免费地点只给出坐标与客观环境，不能保证玩家身边必定生成指定宝藏或必得机缘。

## 二、堪舆专用副 API

- 原计划中的“第二 API 默认不做”在本主题被明确修改为局部例外：玩家主动发动堪舆时，接入额外的专用副 API 跑探索数据。
- 这项修改只服务堪舆、隐藏地点分析与地图预测图标，不自动扩张成常驻的第二叙事模型，也不推翻“不得接付费 API 判定玩家构筑是否超模、矛盾或有 Bug”的既有禁令。
- 一次有效堪舆可以返回一个、多个或没有达到本轮感知门槛的地点候选，不限制为每次只发现一个地点。
- 副 API 根据地点类型与本轮能够推断的信息调用相应地图图标，并可给出预测方位／区域、预测类型、预期危险或品阶，以及可信程度。
- 副 API 输出的是堪舆所得的 **预期情报**，不是已经完成实地验证的客观事实；直接结果可能存在位置、类型、危险度、归属或用途方面的偏差。

## 三、预期情报与事实情报

- 堪舆采用 A＋B 双层流程：直接扫描先在地图上提供预期；玩家随后仍须缩小范围、抵达现场、实地探查、解析禁制与确认入口，才能逐步取得事实。
- 预期层可以对公开、旅行、势力、深层秘密乃至世界真相相关痕迹作出推测，但“可能涉及某类秘密”不等于已经读取该秘密的事实正文。
- 地点的真实类型、精确入口、实际主人、内部结构、危险、资源和世界真相仍由现场证据与对应情报层逐步确认；副 API 不能只凭预测把这些内容一次性全部下发。
- 初次图标表达的是预测类别和可信程度。实探发现预期与事实不符时，应修正图标和说明，并保留“原推定已被修正”的探索痕迹，而不是静默假装首次判断从未存在。

## 四、可信度与团队堪舆

- 预期结果的可信度由本轮实际可用能力综合评定，不使用固定的无条件准确率。
- 评定至少考虑：相关境界水平、团队中实际参与堪舆者可调用的最高堪舆境界、最高神识层级、相关知识、术法、法宝、地形、距离、遮蔽、干扰与当前状态。
- 团队人数本身不直接叠加成准确率；成员必须实际参与本轮探查，其能力才能进入综合评定。
- 高境界与高神识能够提高范围、精度、辨识维度和可信度，但不能把预期层直接变成无条件全知的事实层。

### 龙曦的神识特例

- 龙曦苏醒初期的常态可调用修为与战斗力量需要恢复，但她保留封印前接近飞升层级的巅峰神识基础；两者不机械同步。
- 巅峰神识来自完整保留的真灵、道果框架、真龙血脉与数千年修炼，不得误写成“因为灵识完整，所以神识很高”。
- 龙曦参与团队堪舆时可以显著提高神识侧的综合评定，但实际使用仍有限制，不能无成本持续展开为覆盖九域的全图雷达。
- 具体限制落在可用范围、持续时间、频率、本源消耗还是多项并存，仍待下一轮审批；她对上古事物的知识也不等于自动掌握现世地貌、势力易主与新阵法。

## 五、固定内容、动态内容与防刷

- 世界级秘密、主要传承、势力核心据点、角色专属地点和其他正典锚点继续预先固定，不能因堪舆副 API 动态重写。
- 普通遗迹、灵脉、洞府与局部副本可以依据所在地域的地理、历史、灵气、势力活动与世界状态动态生成。
- 动态地点在第一次有效堪舆中通过一致性约束并正式成立后，立即成为存档内持续存在的世界事实；其空间锚点、基本类型、历史和已发生互动不能被后续搜索随机替换。
- 动态生成代表补全“世界中原本存在但此前尚未具体化的内容”，不是玩家按下按钮后无因创造一座遗迹。
- 同一位置在相同有效堪舆层级和相同世界条件下不能重复堪舆刷取新地点；重复操作没有新的信息价值，也不能重新调用副 API 抽另一批奖励。
- 一次堪舆已经可以发现多个地点；同一区域后来符合何种条件才能再次有效分析，仍待下一轮确定。

## 六、地图图标与持续状态

- 每个达到显示门槛的预测点在地图上建立图标标记；图标由副 API 根据预测类型与已知信息选择。
- 图标首先是玩家认知标记，而不是后台事实标签。未知的主人、存续状态、真实危险和世界真相不能通过图标样式偷跑泄露。
- 地点认知持续经历：预测／疑似、缩小范围、确认入口、已探索、已改变等阶段；实地发现可以补充或修正原图标。
- 已确认地点及玩家造成的开启、破坏、占领、修复、资源变化与关系后果持续留存；重复堪舆不会刷新地点奖励、主人或历史。
- 图标视觉与具体状态字段目前只冻结语义，不在 Phase 0 提前创建前端组件、schema 或变量树。

## 七、用语说明

- 用户原话中的“地府（可能有主、遗弃、坐化）”本稿暂按修士 **洞府／府邸** 理解。
- 如果原意确实是阴司、幽冥或死者世界意义上的“地府”，应另立地点类别，不与普通修士洞府混写。

## 八、当前仍待审批

1. “同一位置”按命名区域、固定网格，还是实际搜索覆盖区判断；
2. 境界、神识、术法、知识、法宝、团队或世界变化中，哪些足以解锁同一区域的再次有效堪舆；
3. 预测结果是否始终对应真实异常，哪些现实遮蔽、诱饵或干扰可以制造假目标；
4. 龙曦巅峰神识的常态展开范围、持续时间、使用频率与透支代价；
5. 副 API 的失败、超时、关闭和数据冲突如何降级处理；
6. 副本／秘境是否必须保持世界内实体与因果连续；
7. 组合式图标需要表达哪些信息维度，哪些必须保持未知。
